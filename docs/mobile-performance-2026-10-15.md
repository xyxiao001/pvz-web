# 移动端与动画资源优化（2026-10-15）

## 已定位的问题

- iPhone Safari 26.5.2 在 `decodeAudioData` 解码原始 `winmusic.mp3` 时抛出 `EncodingError`，首关另外六个音效与选卡音乐通过。开始关卡的 `Promise.all` 等待该音效，因此所有关卡卡在角色准备完成。用户在同设备对照确认 44.1 kHz、96 kbps MP3 可解码，替换运行时地址后确认正常进入；原文件保留为生成源。
- 手机全屏只有细线：移动端网格布局继承桌面全屏 `justify-content:center`，内部尺寸容器使自动列宽收缩到 4 px。改为明确宽高的块布局，浏览器复现前后为 4 / 844 px，用户 Android Chrome 确认修复。Manifest 声明 landscape；已安装应用的清单更新时间由 Chrome 管理。
- 卷心菜、玉米、西瓜投手原始逐帧动画每帧 10 tick（100 ms）。高显示刷新率无法弥补姿态之间的停顿。当前将三种投手的待机、投掷接入原 Reanim 部件插值，保持待机周期 310/190/310 tick 和既有攻击展示窗口 50/50/155 tick。原卷心菜/玉米攻击只在 50 tick 窗口播放长达 380/340 tick 的片段开头；新动画在窗口内完成投掷。未改逻辑出弹时机、伤害、移动速度或关卡。

## 文件体积

采用 WebP quality 90 压缩背景与逐帧图集；卡片、文字 UI、部件图集保持无损，2× 尺寸与透明通道不变。HD PNG 母版保留，可由现有导出工具重建。压缩具有 RGB 损失，并非无损优化。

| 资源 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 泳池背景 | 4,226,648 B | 473,708 B |
| 投石车发射图集 | 3,856,816 B | 886,378 B |
| 本批 202 张图 | 239,991,714 B | 50,390,568 B |
| 三种投手待机与攻击资源 | 6,004,980 B | 496,065 B |

图集总体减少约 79%；三种投手改为 JSON + 共用部件图，约减少 92%。生产包排除已被部件动画替代的逐帧页面。PNG 母版与旧页面不随生产包下载，首页继续按需加载。压缩不减少相同尺寸图片解码后的 RGBA 内存；纹理内存下降来自投手改用共用部件。

## 渲染取样与范围

桌面内置 Chromium、800×600 逻辑战场、45 株投手与 20 只僵尸，同一固定场景，30 帧预热后采样 180 帧。纹理占用按上传图片尺寸 × 4 估算，不是进程总内存；帧间隔来自 requestAnimationFrame，CPU 耗时包含场景更新和 Pixi render 调用，不代表 GPU 完成时间。

| 实现 | CPU 中位数 | CPU P95 | 帧间隔 P95 | 纹理估算 |
| --- | ---: | ---: | ---: | ---: |
| 旧逐帧 | 0.30 ms | 0.50 ms | 8.9 ms | 93.40 MiB |
| 新插值，血条关闭 | 0.80 ms | 1.50 ms | 9.3 ms | 69.75 MiB |
| 新插值，血条开启 | 1.10 ms | 2.40 ms | 9.3 ms | 69.75 MiB |

这是用约 1 ms 的 P95 CPU 增量换取连续的部件运动和较少纹理，并非 CPU 耗时下降。血条测试为缓存计算优化前数据，可作为保守参考。不能据此承诺所有手机的帧率。普通僵尸与其余未迁移植物仍使用离散帧，本轮未将全部角色转换为部件动画。

## 血条与验证

设置和暂停菜单均可开关，默认关闭，当前页面会话内保留，不写存档。血量包含本体、头盔和盾牌，迷你僵尸分别取整；僵王继续使用原有底部生命条。使用共用白纹理绘制，随角色移动，关闭后隐藏，死亡动画不显示；数值不变时不重算比例和宽度。

251 项测试通过，包含新增投手插值/周期与护甲、盾牌、迷你血量规则；生产构建通过。4,622 帧和 108 张静态图片的尺寸/透明度与母版校验通过，无损 UI 的 RGBA 保持一致。未运行 lint。浏览器对照检查旧/新动画、开启血条、生产关卡资源与设置交互。
