# 资源与性能优化记录

基线：`d23606d`。本轮保留 2× 战斗画质、动画帧、时序、游戏速度和战斗规则。原始测量数值见 [performance-metrics.json](performance-metrics.json)。

## 加载顺序与资源大小

首页仍只加载界面，PixiJS 与战斗资源在进入关卡后加载；首页背景增加 HTML 高优先级预加载，避免等主模块执行、CSS 生效后才发现该图。选卡关卡继续等确认六张卡后加载对应植物及本关敌人。传送带、初始已有植物和恢复存档需要先准备场上角色，保持原流程。

动画与静态战斗纹理的下载、解码和 GPU 上传限制为四个并发任务；僵王部件下载也限制为四个。没有新增自动重试、备用画质或缺图替代。加载失败仍向上传播。PWA 前台请求取得网络响应后即可使用，缓存写入交给 `FetchEvent.waitUntil`；安装和主动下载离线资源仍等待写入完成。测试模拟尚未完成的缓存写入，确认前台响应不被其阻塞。

五张无尽场景预览改用 800 像素宽的独立缩略图：15.38 MiB → 1.67 MiB（约减少 89%）。仅缩略图缩小，战斗背景不变。

动画图集尝试多种排布宽度、裁掉空白边缘，并提高无损 WebP 编码努力等级。194 张图集总数不变；181 个片段、4622 帧的 RGBA 像素、锚点与时长不变。全部图集的估算 RGBA 占用 988.61 MiB → 896.96 MiB，降低约 9.3%。**全部图集不会同时加载。**

| 动画资源集合 | 解码 RGBA 优化前 → 后 | 下载优化前 → 后 |
| --- | --- | --- |
| 1–1 | 30.35 → 27.27 MiB | 7.22 → 7.14 MiB |
| 3–9 指定六卡 | 287.91 → 261.48 MiB | 58.44 → 57.73 MiB |
| 5–9 指定六卡 | 453.45 → 416.59 MiB | 98.76 → 97.61 MiB |
| 5–10 | 667.57 → 608.67 MiB | 137.03 → 135.49 MiB |

表中只统计动画图集，未含背景、僵王独立部件、音频及渲染缓冲区；选卡名单记录在测量脚本的对应测试配置中。无损重新编码对下载量只有约 1% 的改善，不能将纹理内存降幅当成网络流量降幅。

生产构建增加明确的运行资源复制步骤：只包含 runtime、音乐、音效、应用图标和 manifest。原标准构建会复制约 583.86 MiB 的 public 内容；当前完整 dist 约 264.90 MiB。此前人工暂存发布已经排除了大部分制作母图，因此这不是“线上包从 584 MiB 降到 265 MiB”。开发素材继续保留在仓库，本地素材工具仍可使用。

## 内存生命周期

返回首页和切换关卡时，停止渲染，清空战斗对象，销毁帧纹理及裁切纹理，卸载对应 Assets 资源与僵王部件。下一关等待卸载完成，避免新旧战斗纹理叠加。轮间重新选卡继续复用仍然需要的动画。

浏览器测试页实测：

- 泳池六卡阵容：58 个纹理源，约 275.12 MiB RGBA；释放后为 0，1506 个纹理对象全部销毁。
- 僵王关卡（包括独立部件）：169 个纹理源，约 660.92 MiB RGBA；释放后为 0，2469 个纹理对象全部销毁。
- 真实首页 → 1–1 开始 → 暂停 → 首页 → 再进 1–1 正常；控制台无 error/warn。

这些是应用持有的纹理统计及像素占用估算，不是浏览器进程 RSS；显卡驱动、浏览器图片缓存、音频与帧缓冲另占内存。HTTP/PWA 磁盘缓存仍保留，用于重进关卡。没有主动删除旧版本离线缓存。

## 战斗 CPU

原先每只僵尸每个逻辑帧都会复制并排序全场植物。改为单次遍历，保持南瓜 → 普通植物 → 底座的优先级和相同优先级下的原顺序。子弹命中也改为单次遍历取最靠左的合格目标，保留同位置目标顺序。僵王绘制复用矩阵，减少每帧临时对象。

可复现命令：`pnpm exec tsx tools/benchmark-simulation.ts`。场景为 100 只僵尸、每行六格坚果＋南瓜，固定随机种子；执行 1000 个逻辑帧，预热一次后取五次中位数。同一机器 Node 环境测得：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 白天 | 406.89 ms | 49.31 ms |
| 泳池 | 489.31 ms | 52.65 ms |
| 屋顶 | 504.26 ms | 51.27 ms |

三组完整存档 SHA-256 与优化前完全相同，回归测试固定这些结果。此为密集阵容的逻辑计算基准，**不代表浏览器 FPS 提高八至十倍**。

## 验证与剩余限制

`pnpm test`：207 项全部通过；`pnpm build`：通过。`python3 tools/check-runtime-assets.py`：4622 帧和 108 张静态图与高清母图 RGBA 逐像素一致。并发上限、错误传播、缓存写入异步完成、确定性战斗结果均有测试。未运行 lint。

高阶关卡的 2× 帧图集仍是主要体积和内存来源，僵王关卡尤其明显。后续若进一步采用有损图集、降低分辨率或按波次加载，需要分别评估画质、网络较慢时的资源就绪时机；本轮没有引入这些行为。没有在移动设备或受限移动网络上做实机基准，因此不承诺统一加载秒数或 FPS。
