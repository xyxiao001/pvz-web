# 资源与性能优化记录

基线：`d23606d`。本轮保留 2× 战斗画质、动画帧、时序、游戏速度和战斗规则。原始测量数值见 [performance-metrics.json](performance-metrics.json)。

## 加载顺序与资源大小

首页仍只加载界面，PixiJS 与战斗资源在进入关卡后加载；首页背景增加 HTML 高优先级预加载，避免等主模块执行、CSS 生效后才发现该图。选卡关卡继续等确认六张卡后加载对应植物及本关敌人。传送带、初始已有植物和恢复存档需要先准备场上角色，保持原流程。

动画与静态战斗纹理的下载、解码和 GPU 上传限制为四个并发任务；僵王部件下载也限制为四个。没有新增自动重试、备用画质或缺图替代。加载失败仍向上传播。PWA 前台请求取得网络响应后即可使用，缓存写入交给 `FetchEvent.waitUntil`；安装和主动下载离线资源仍等待写入完成。测试模拟尚未完成的缓存写入，确认前台响应不被其阻塞。

五张无尽场景预览改用 800 像素宽的独立缩略图：15.38 MiB → 1.67 MiB（约减少 89%）。仅缩略图缩小，战斗背景不变。

动画图集尝试多种排布宽度、裁掉空白边缘，并提高无损 WebP 编码努力等级。194 张图集总数不变；181 个片段、4622 帧的 RGBA 像素、锚点与时长不变。全部图集的估算 RGBA 占用 988.61 MiB → 896.96 MiB，降低约 9.3%。**全部图集不会同时加载。**

| 动画资源集合 | 解码 RGBA 优化前 → 后 | 下载优化前 → 后 |
| --- | --- | --- |
| 1–1 | 30.35 → 27.27 MiB | 7.22 → 7.14 MiB |
| 3–9 指定六卡 | 287.91 → 261.48 MiB | 58.44 → 57.73 MiB |
| 5–9 指定六卡 | 453.45 → 416.59 MiB | 98.76 → 97.61 MiB |
| 5–10 | 667.57 → 608.67 MiB | 137.03 → 135.49 MiB |

表中只统计动画图集，未含背景、僵王独立部件、音频及渲染缓冲区；选卡名单记录在测量脚本的对应测试配置中。无损重新编码对下载量只有约 1% 的改善，不能将纹理内存降幅当成网络流量降幅。

生产构建增加明确的运行资源复制步骤：只包含 runtime、音乐、音效、应用图标和 manifest。原标准构建会复制约 583.86 MiB 的 public 内容；当前完整 dist 约 264.90 MiB。此前人工暂存发布已经排除了大部分制作母图，因此这不是“线上包从 584 MiB 降到 265 MiB”。开发素材继续保留在仓库，本地素材工具仍可使用。

## 内存生命周期

返回首页和切换关卡时，停止渲染，清空战斗对象，销毁帧纹理及裁切纹理，卸载对应 Assets 资源与僵王部件。下一关等待卸载完成，避免新旧战斗纹理叠加。轮间重新选卡继续复用仍然需要的动画。

浏览器测试页实测：

- 泳池六卡阵容：58 个纹理源，约 275.12 MiB RGBA；释放后为 0，1506 个纹理对象全部销毁。
- 僵王关卡（包括独立部件）：169 个纹理源，约 660.92 MiB RGBA；释放后为 0，2469 个纹理对象全部销毁。
- 真实首页 → 1–1 开始 → 暂停 → 首页 → 再进 1–1 正常；控制台无 error/warn。

这些是应用持有的纹理统计及像素占用估算，不是浏览器进程 RSS；显卡驱动、浏览器图片缓存、音频与帧缓冲另占内存。HTTP/PWA 磁盘缓存仍保留，用于重进关卡。没有主动删除旧版本离线缓存。

## 战斗 CPU

原先每只僵尸每个逻辑帧都会复制并排序全场植物。改为单次遍历，保持南瓜 → 普通植物 → 底座的优先级和相同优先级下的原顺序。子弹命中也改为单次遍历取最靠左的合格目标，保留同位置目标顺序。僵王绘制复用矩阵，减少每帧临时对象。

可复现命令：`pnpm exec tsx tools/benchmark-simulation.ts`。场景为 100 只僵尸、每行六格坚果＋南瓜，固定随机种子；执行 1000 个逻辑帧，预热一次后取五次中位数。同一机器 Node 环境测得：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 白天 | 406.89 ms | 49.31 ms |
| 泳池 | 489.31 ms | 52.65 ms |
| 屋顶 | 504.26 ms | 51.27 ms |

三组完整存档 SHA-256 与优化前完全相同，回归测试固定这些结果。此为密集阵容的逻辑计算基准，**不代表浏览器 FPS 提高八至十倍**。

`pnpm test`：207 项全部通过；`pnpm build`：通过。`python3 tools/check-runtime-assets.py`：4622 帧和 108 张静态图与高清母图 RGBA 逐像素一致。并发上限、错误传播、缓存写入异步完成、确定性战斗结果均有测试。未运行 lint。

## 2026-10-14：植物连续动画与全屏遮挡

基线 `150fcec`。三线射手旧图集每循环 144 tick、16 张姿态，在 1× 下约 11.1 个姿态/秒；豌豆和向日葵为 25 个姿态/秒。即使浏览器持续渲染，这种整帧替换仍会产生顿挫。本次仅将这三种植物的待机循环替换为原版 Reanim 部件插值，保留 Web 版已有循环时长、射击时机、伤害及倍速规则。其他角色仍使用原来的图集。

源码依据：Portable `141c1476dd462ac3526f796e303177616f4de6bc` 的 `src/PvzpLib/Reanimator.cpp:571`（`GetTransformAtTime`）、`:1020`（`GetAttachmentOverlayMatrix`）及 `src/Lawn/Plant.cpp:220–284`。插值位置、缩放、偏斜角和透明度，三线射手三个头使用当前挂点矩阵乘绑定姿态的逆矩阵。资源来自 ruslan `325b2229a7225d73870bb69322eefcda3a45bf8d`；文件哈希见 [plant-motion-assets.json](plant-motion-assets.json)，导入脚本为 `tools/import-plant-motion.py`。部件沿用 Real-ESRGAN animevideov3 2× 制作流程。这是三个待机动画的接入，不代表已经迁移原版完整动画状态机。

这些部件只随选卡或存档中的对应植物加载，开始前完成 GPU 上传，退出后卸载。三种植物合计资源由 1,779,998 bytes 的旧图集替换成 370,012 bytes 的部件图集和姿态 JSON；纹理解码像素由 5,193,872 bytes 降至 1,605,632 bytes。原图集仍保留在资源库中，但这些植物在战斗中不再加载它们。

渲染缓冲分辨率上限设为世界坐标的 2×，与现有高清素材一致。桌面 DPR 2、画布显示宽 1190 CSS px 的对照场景中，缓冲由 2380×1785 降为 1600×1200，像素数减少 54.8%。低于此上限的屏幕仍按实际显示密度渲染。

密集渲染对照包含 30 株上述植物、10 株睡莲、30 只僵尸和 30 发子弹；每组预热 30 帧后测量 180 帧。1× / 2× / 4× 的 CPU 渲染调用 P95 分别由 0.6 / 0.3 / 0.3 ms 变为 0.7 / 0.7 / 0.6 ms；帧间隔 P95 由 10.1 / 9.1 / 9.5 ms 变为 9.4 / 8.9 / 8.7 ms。部件插值增加少量 CPU 工作，主要收益是连续姿态与更小的纹理、缓冲；此测试不包含完整战斗逻辑，也未等待 GPU 完成，不能解释成统一 FPS 提升。原始记录见 [plant-motion-render-metrics.json](plant-motion-render-metrics.json)。

战斗 HUD 改成独立的 87 逻辑像素顶部栏，下方保持完整 800×600 战场，窗口与全屏均按 800×687 比例适配。1280×720 全屏验证中 HUD 底边与画布顶边同为 y=98.078，战场完整落在视口内；真实 3–4 关第一排种植、暂停正常。资源释放后部件加载数和旧片段数均为 0。

验证：215 项测试通过、TypeScript 与生产构建通过，真实关卡控制台无 error/warn；未运行 lint。

## 2026-10-14：原部件动画变换与资源并行

基线为 `f6d1cf9`，覆盖豌豆射手、向日葵、三线射手、机枪射手、双子向日葵和冰西瓜。此前每个部件每帧经过 `poseMatrix → Container.setFromMatrix → Matrix.decompose → updateLocalTransform`：已知的位移、缩放和两个倾斜角先合成矩阵，再经 `atan2`、平方根拆开，随后再次合成。现在直接写入 Pixi 的 position / scale / skew，保留挂接根节点的矩阵运算。坐标关系为 `skew.x = -ky`、`skew.y = kx`，旋转为 0，负缩放原样保留。未跳过动画帧或更改播放时间。

同一 Node 进程对优化前后交替测量：60 株混合原部件植物、600 帧，包含局部矩阵重建；预热两轮后记录七轮。中位数从 235.74 ms 降到 80.34 ms，减少 65.92%。使用空纹理，不包括 GPU 绘制、贴图解码和战斗模拟，因此不能解释为整场 FPS 提升 66%。原始数值与方法见 [plant-motion-performance.json](plant-motion-performance.json)。

每株原部件植物的 JSON 和 WebP 现在同时发起请求，去掉等待 JSON 下载完成才开始请求贴图的串行依赖。仍最多准备三株植物，即最多三组 JSON/贴图请求；GPU 上传完成后才可进入战斗。按选卡加载、退出释放、原有错误传播和 PWA 缓存策略不变。

验证：231 项测试和生产构建通过。新增测试遍历六种植物所有待机轨道及冰西瓜投掷轨道，在帧间 0 / 0.25 / 0.5 / 0.75 / 1 处比较六个仿射矩阵分量，同时检查负缩放与零缩放。浏览器对照原/新渲染路径，抽查抬手和出弹时最大矩阵差值分别为 1.11e-16、2.22e-16，属于浮点误差。战斗数值、帧率/倍速一致性与既有密集战斗快照继续通过。未运行 lint。
