# 火豌豆与无尽渲染复核（2026-10-15）

## 火豌豆

之前 `Scene.render` 对火豌豆仍使用普通 `pea.webp`，仅加橙色 tint，因而没有火焰、尾焰和火星。

现在用原始 `FirePea.reanim` 的五条轨道烘焙 25 帧到一个 2 倍 WebP 图集；原始输入 SHA-256 和图集尺寸记录于 `fire-pea-assets.json`。生成工具为 `tools/import-fire-pea.py`，重用现有 Reanim 离线解析器。运行时每发子弹仍为一个 Sprite，不创建逐火星粒子对象。

行为依据：[Portable Projectile.cpp::ConvertToFireball（1208–1218）](https://github.com/wszqkzqk/PvZ-Portable/blob/141c1476dd462ac3526f796e303177616f4de6bc/src/Lawn/Projectile.cpp#L1208)。原版以 50–80 fps 循环此 Reanim；Web 用子弹 ID 产生稳定的视觉速率差异，保持游戏 RNG、伤害和弹速不变。反向豌豆翻转火焰方向。图集新增 141,944 字节，解码 RGBA 约 1.37 MiB，仅在选中／保留火炬树桩或存档中已有火豌豆时加载；离开战场释放。

## 密集场景优化

- 子弹显示对象复用：未使用池最多保留 256 个，切关时全部释放。不会限制正在显示的子弹数量。
- 每行子弹共用排序容器，新增子弹不再触发整片战场所有角色重新排序。
- 屏幕外僵尸跳过部件姿态计算，保留动画时间与状态；进入视野后显示当前姿态。范围预留 220 像素，包含巨人、旗帜和蹦极附件。
- 植物、普通僵尸、巨人姿态参数不变时直接复用，减少冻结、睡眠与暂停期间的重复计算。移动、攻击和可见动画仍按原来的插值频率更新。

## 实测

本机 Codex 内置 Chromium、800×600 逻辑画布、DPR 2。相同固定阵容包含 72 株植物（含睡莲）、150 只僵尸、240 发普通子弹，开启血条；先预热 30 帧，再采样 240 帧。子弹循环经过边界并换 ID，模拟持续生成和消失。此对照刻意保持子弹画面一致，不把新增火焰效果的绘制成本混入旧版静态豌豆对照。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 更新场景并提交绘制 CPU 中位数 | 2.5 ms | 2.2 ms |
| CPU P95 | 3.5 ms | 3.0 ms |
| 浏览器帧间隔 P95 | 8.8 ms | 9.0 ms |
| 采样全过程不同子弹显示对象数（含预热） | 732 | 246 |
| 保留池对象数 | 0 | 6 |
| 参与显示的僵尸数 | 150 | 126（24 只在屏幕外） |

这是单次桌面受控对照，不是 GPU 时间、长期内存测量或移动端 FPS 保证。可确认对象创建减少约 66%，CPU 中位耗时减少约 12%；显示帧间隔基本持平。未调整模拟步长、敌人数、战斗属性、渲染分辨率或动画采样率。
