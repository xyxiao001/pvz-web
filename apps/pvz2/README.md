## 与 PVZ1 的边界

PVZ1 保留在根项目，PVZ2 的代码、素材、依赖声明、测试和构建配置均在本目录。两者不导入对方的游戏逻辑、渲染器和资源，复用固定步长模拟、模型与渲染分离、按需加载、纹理预上传等设计。游戏之间通过页面跳转切换。

`pvz2-web:<关卡 ID>-complete` 分别保存各关通关记录，首关仍使用原来的 `pvz2-web:egypt1-complete`。`pvz2-web:map-rewards` 记录已获得的地图奖励，`pvz2-web:pending-map-completion` 记录待播放的返图流程。`pvz2-web:campaign-rewards` 记录道具奖杯、幼苗、皮纳塔、便条、世界钥匙和金币袋的首通领取记录。`pvz2-web:world-navigation` 保存世界选择及各地图浏览位置，`pvz2-web:audio` 保存二代音量，`pvz2-web:free-play` 保存自由选关开关。不会读写 PVZ1 存档。

PVZ2 在 PVZ1 的 Service Worker 清单生成后才拼入发布目录，不参与一代离线下载。两版仅共用 worker 实现，各自生成文件清单和版本；PVZ2 的 worker 位于 `/pvz2/sw.js`，作用域、应用标识和启动地址均为 `/pvz2/`，缓存按该路径与 PVZ1 分开。

## 安装、离线与更新

世界地图 → 设置 → 安装与更新，可查看当前版本、缓存进度，使用浏览器安装入口，或手动下载完整离线资源。安装图标使用二代独立的时空门与数字 2 图案。

启动只预缓存入口、样式、清单与图标；地图、角色、音乐和动态战斗代码按访问缓存。完整离线前点击“下载离线资源”，等待“离线资源已就绪”。本轮全部资源约 221 MiB，实际大小以管理面板为准。

新版本就绪后可选择“稍后”，或点击“更新并重新加载”；更新会重新打开游戏，请先完成当前关卡。内容哈希未变化的素材继续复用，更新不修改存档。开发模式不注册 worker，安装和离线测试使用生产预览。使用步骤、隔离规则及验证边界见 [PWA 文档](../../docs/PWA.md)。

## 运行与验证

在仓库根目录执行：

```sh
pnpm install
pnpm dev             # PVZ1 :5173；PVZ2 :5174，经 :5173/pvz2/ 代理访问
pnpm dev:pvz2        # 单独启动 PVZ2，访问 http://127.0.0.1:5174/pvz2/
pnpm test:pvz2
pnpm build:pvz2      # 独立输出 apps/pvz2/dist/
pnpm build           # 组合到 dist/ 与 dist/pvz2/
pnpm preview         # 同一站点预览两版 PWA
```

`pnpm test` 运行 PVZ1 测试。根目录 `pnpm preview` 预览组合构建。单独预览二代可运行 `pnpm --filter pvz2-web preview --port 4175`，访问 `http://127.0.0.1:4175/pvz2/`。地图测试覆盖原始连线、解锁状态、浏览边界、动画资源引用及输出哈希；战斗测试保留原有十波通关与植物技能验证。

## 加载与后续接关

`src/shell/controller.ts` 管导航与 DOM 交互，`renderer.ts` 管独立动画时钟、相机和 Pixi 绘制，`navigation.ts` 管原地图节点状态与关卡路由。`progression.ts` 管通关和奖励状态，以及原版半秒间隔的返图事件。`game/levels.ts` 登记已迁移关卡的资源、名称、选卡范围与首通奖励；选卡在每次进入时读取已获得植物。新增战斗入口时同步扩展 `LEVEL_ROUTES` 与关卡配置，战斗模型和资源仍需逐关迁移。

首屏加载世界选择及共用 UI；进入世界后才请求该地图的 JSON、骨骼和 WebP 图集。骨骼两组并发加载并预上传纹理，离开地图释放其图集；远处的前景实例按可见范围创建和释放。音乐在首次交互时请求。原字体按外层、已迁移关卡 UI 和对白文案提取为约 210 KB WOFF2，保持原字形。

埃及第 2–35 关的 campaign 素材共约 28.52 MB，按关卡和可用植物加载相应图集；夜间庭院仅第 4、5、7、8、16、18、23、24、25、29、33、35 关加载。退出战斗时销毁渲染器、动画时钟和事件监听，纹理仍复用资源缓存。道具图标只在第 5 关加载，卡片仅生成本局可用植物及首通奖励。

13 个世界的外层资源合计约 43.6 MB（文件大小，含音乐，不含脚本和现有约 5.05 MB 战斗资源），不会一次全部下载。新增世界介绍资源约 0.93 MB，在打开介绍时加载；首关 UI、角色、粒子和音效约 5.05 MB，在进入战斗时加载。地图和首关战斗分别使用动画时钟；进入战斗时停止地图，返回时恢复。战斗代码与样式动态导入，样式限定在 `.battle-app` 内。

## 埃及第 1 关

流程为首次角色入场与对白 → 角色退场 → 镜头浏览庭院和街道 → 四种可用植物的自由选卡 → 镜头回场 → 准备／安放／种植 → 十波战斗 → 首次地图奖励 → 返回地图。再次进入已完成关卡会跳过首次对白和首次奖励。暂停可调整音量、重新选卡或返回地图；战斗支持二倍速。通关领取奖励后，第 2 关节点按原地图连线开放。

使用原始戴夫、温妮、植物、僵尸、阳光、小推车骨骼，卡片、阳光槽、铲子、按钮和进度条来自原资源。卡片复用地图已加载的图集。四种植物可选择、取消和重新排列，未选择的植物不能在本局种植。

本轮已接入原版镜头时序、NPC 入退场和分句语音、断臂／掉头／倒地／淡出、小推车碾压、种植与铲除泥土、豌豆弹体与命中、土豆雷出土和爆炸。伤害与移除读取骨骼事件帧；最后一只僵尸的死亡演出完成后才显示结算。阳光支持向日葵抛出、落地计时、飞向计数器，以及太阳神的分段吸收、变色和法杖挂点追踪。路障帽子使用更新后的骨骼变换，修复朝向错误。

## 来源与可重复提取

来源：[PvZ2 Gardendless](https://github.com/Gzh0821/pvzge_web)，固定提交 `0e4a05348b6de328e2902a57afa24a3a454a4205`。从 Cocos 构建产物读取场景、嵌套预制体、属性覆盖与 DragonBones 资源，在独立应用中实现导航和渲染；无需运行其 Cocos、Bullet、Spine WASM，也没有还原原始 TypeScript 工程。

`asset-provenance.json`、`shell-provenance.json`、`battle-provenance.json`、`window-provenance.json`、`progression-provenance.json` 和 `campaign-provenance.json` 记录各资源组的输入／输出 SHA-256。`UPSTREAM-LICENSE` 保留仓库许可证文本，不代表对第三方美术、音乐另行授权。

```sh
# 战斗资源需要 Pillow；地图额外需要 fonttools 和 brotli。
python3 tools/pvz2-assets/extract.py
python3 tools/pvz2-assets/extract-shell.py
python3 tools/pvz2-assets/extract-world-window.py
python3 tools/pvz2-assets/extract-first-level.py
python3 tools/pvz2-assets/extract-progression.py
python3 tools/pvz2-assets/extract-egypt-campaign.py
python3 tools/pvz2-assets/extract-pirate.py
python3 tools/pvz2-assets/extract-font.py
```

下载及纹理编码缓存放在忽略目录 `artifacts/pvz2-source/`。传送门引用普通关卡的两套光线子骨骼，提取时显式合并这一依赖；其余骨骼保留上游结构。字体子集取自世界名称、介绍、当前控制器文案和首关对白，修改文案后重新执行地图提取脚本。

### Local store

The store uses the pinned native category tabs, commodity panels, currency buttons and product art. `extract-store.py` exports its catalog and records hashes in `store-provenance.json`; store art loads on first opening.

`pvz2-web:wallet` stores coins, gems, tickets and one-time purchases independently from PVZ1. Gems start at 99999 once; reopening or refreshing does not replenish them. Coin/gem bundles retain upstream prices. All five native shop upgrades are available: seed slot, plant-food slot, starting sun, sun-shovel refund and manual mower. They stack with earned map rewards. Each sun-shovel tier adds 25% refund, split into native multiples of five; each manual-mower tier adds one launch per battle. Hold a mower for one second without a selected card/tool to launch it; moving away, releasing or pausing cancels the hold. Native Trans events, hold-circle art and launch audio are retained. Iceweed and Snowdrop retain the Egypt 9/28 completion prerequisites and become selectable in normal battles from day 2 onward. Day 1 retains its tutorial roster. Fixed decks and conveyor pools remain authored by the level.

Other shop plants, costumes and battle coin settlement are not implemented. Garden purchases and tickets are described below. Store product previews currently use native idle stills. Locked map nodes now follow upstream `WorldMap.ts`: clicking does not open a dialog. The old migration explanation has been removed.

`tests/store-visual.html` exercises purchases and battle entry with a separate memory profile.

### Scene resources and world configuration

`src/game/worlds/egypt.ts` owns Egypt's level roster, mode, rewards, narrative, lawn and music. `levels.ts` is the battle registry. `rendering/resource-plan.ts` derives actors and effects from actual plants, waves, summons and challenge modules rather than day-number ranges. Future world registrations still require their own gameplay/actor support; registering a map alone does not make its levels playable.

Map, store previews and battle each hold explicit texture leases. Store snapshots release their source textures after capture; battle teardown awaits release of its own textures. Shared map/card textures remain alive while another view holds them. Pixi global batch pools remain owned by the surviving map application.

The resource-plan comparison used identical actor sets and all available Egypt plants (or the native preset/conveyor pool), with WebP byte sizes and RGBA pixel sizes from exported atlases. Egypt 23 decreases from 26 to 20 unique atlases: 5,965,886 to 5,504,380 WebP bytes and 118,816,768 to 108,789,760 RGBA bytes. These figures describe texture assets, not measured browser heap or load-time improvements.

`tests/resources.test.ts` covers shared ownership, reentry during asynchronous unloading and dependency resolution for all 35 levels. `tests/upgrades-visual.html` purchases the two upgrades in a separate memory profile and exercises hold/startup/removal/refund. `tests/map-visual.html` covers repeated battle disposal with a live map renderer.

## 可切换素材画质

世界地图的“设置 → 画质”提供轻量版、原图无损版、4K 增强版。默认沿用现有轻量素材，切换后重新加载并保存选择。地图、角色及动画贴图按档位加载，字体、音频、动画数据和静态界面图共用；存档与关卡规则不变。

原图无损版从固定上游 PNG 编码为无损 WebP。增强版使用本地 `realesr-animevideov3-x2` 放大两倍，透明通道由原图以 Lanczos 放大，再编码为无损 WebP。它是超分处理结果，不是原生 4K 美术；部分纹理会更平滑，贴图显存约为对应原图的四倍。仅按当前场景请求所选版本；现有“下载离线资源”会包含全部档位。

`python3 tools/pvz2-assets/build-quality-packs.py` 从原资源导出流程留下的固定版本缓存构建素材，依赖 Pillow 和 `artifacts/hd-work/runtime` 下已有的 Real-ESRGAN 程序及模型。新导入贴图后需重新运行。输出为 `public/assets/quality/`、`src/assets/quality-manifest.json` 和记录来源及哈希的 `quality-provenance.json`；不同世界复用的源图只输出一份。

`tests/quality-visual.html` 提供相同位置、相同姿态的舞池地图和植物对照，不修改玩家设置或存档。可在 3840×2160 视口切换三档检查轮廓、透明边缘及图集坐标。
